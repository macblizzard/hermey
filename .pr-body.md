Two things, both asked for on 2026-11-16.

## 1. The bot face performs

*"it now blinks and moves a bit, but it's not enough … more eye movements and some jumps and flips in between every few seconds while working."* Decisions he took in the same conversation: **playful**, in **working + every busy state**.

- **Body**, on a 5.2–6.1 s beat: crouch → launch → apex → landing squash, then next beat a 360° roll or an out-and-back 180° twist, direction alternating.
- **Eyes**, faster clock: a saccade every ~0.9 s (60 ms move, hold, return), a two-step double take every fifth, a squint on a 3.4–4.2 s clock of its own.
- Nothing is state: every value is sampled from the clock and the bot's phase, so two faces never jump in lockstep and one instant always draws one face.
- Idle, waiting and error untouched; Reduce Motion, the Appearance switch and the size floor still close the face; the leap is capped in points (2.6 pt at 16 pt, 4.8 pt at 96 pt).
- A layer, not an edit to the port: `BotAvatarMotion.frame` stays what the parity tests pin, `BotAvatarPerformance` composes over it.

Spec: `docs/requests/2026-11-16-bot-stunts.md`. Thresholds in the tests were computed first from a Python transcription of the sampler.

## 2. Why the chat lagged behind the list and the notification

*"why is it that i get a new msg from u on bot list and notification but it loads on chat much later."*

Not the network. The row, dot and banner come from the 25 s sweep that reads every bot's newest host message; the chat comes from a resume that `endlessSession` **skipped for up to two minutes** after leaving a bot, on the assumption that "anything said since arrives on the live socket". It doesn't: every branch of `apply(_:)` returns early for a session that is not on screen, so another bot's reply is dropped, not buffered. Opening that bot on the strength of its banner painted the pre-reply snapshot and asked the host nothing.

Fixes, none of which compares the host clock with the device clock:

- `unseenSessions` — the socket named a session that was not on screen (bounded).
- `conversationCacheHostStamp` — the host stamp the snapshot contained vs the host stamp now.
- `transcriptHostStamp` + `reconcileOpenChatWithHost` — an *idle open* chat is now re-read when the sweep sees the host has written, which also covers messages that produce no socket event at all (another device's turn, an agent posting outside a run, a bot-to-bot transfer). Settles: an unchanged stamp re-reads nothing.
- The comment claiming `.messageComplete` raises the dot for another bot was false (unreachable under its own guard) and is corrected.

`StaleConversationTests`: the list-announced reply opens in the chat, a session's own event forces the read with no sweep, an idle chat re-reads on host news, an unchanged stamp settles, and nothing-new still comes from the cache.
