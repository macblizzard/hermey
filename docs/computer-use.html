Local computer use

Let bots use the Mac you are sitting at — screen, mouse, keyboard, files — over the app's own outbound link. No SSH, no Remote Login, no inbound port.

How it works

The Mac app is the executor. Your host sends a command; the app performs it under your account and returns the result. The Mac dials out and keeps the socket open, so nothing listens on it and Remote Login stays off.

With the switch on, that socket comes up when the app launches and redials itself after a drop. Opening Settings is never what switches it on.

It starts switched off. Nothing is queried until you turn on Settings → Computer → Let bots use this computer.

What bots can do

  • Run one-shot commands — including local builds — with a working directory you choose.
  • Capture the screen with active-window metadata, then click, type, use keys, scroll or focus an app.
  • Read, write and list files in one shared workspace, including downloads from the private browser surface.
  • Open URLs and inspect a page snapshot without leaving the conversation.

macOS permissions

Each grant has its own status row and its own link into System Settings. Nothing is requested just by opening Settings — the probes run only when you press a button.

GrantWhat it is for
Accessibilityclicks and keystrokes
Screen Recordingcaptures
Input Monitoringdetecting physical input so a bot can be taken over
Automationdriving an app through AppleScript

How it stays contained

  • Computer use starts switched off, and revoking the Mac closes its link immediately.
  • One sorted queue drives the desktop, so two bots cannot interleave actions — and every action is attributed to the bot that asked.
  • Physical input pauses the batch: touching the machine takes control back, and the bot resumes only when you hand it back.
  • The app must be running. When it closes, computer use reports the Mac as offline.
  • The host pings the Mac and drops a socket that stops answering, so a slept machine reads as absent instead of hanging a caller.

The workspace

File tools are confined to one shared folder under ~/Library/Application Support/Hermey/Computer/Workspace/. Every bot sees the same folder; paths that climb out of it are refused and audited.

From a bot's shell

hermey computer observe
hermey computer act '[{"kind":"click","x":120,"y":80}]'

The same commands are documented for agents in the shared mac-local-computer skill that the bridge installs for every bot on the host.
