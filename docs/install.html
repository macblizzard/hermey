Install the host

One command on the machine that already runs Hermes. It adds a loopback service and exposes it over your tailnet — nothing else on the host changes.

The one command

curl -fsSL https://github.com/macblizzard/hermey/releases/latest/download/install.sh | sudo bash

Re-running it is an upgrade: same units, same state, package reinstalled and the services restarted.

What it does, in order

  1. Preflight. Python 3.11+, systemd, and a hermes binary it can find. It stops with a clear message rather than half-installing.
  2. Service account. The bridge runs as the owner of the Hermes home — the account that can already read your bots' profiles. HERMEY_USER names a different one if you prefer; it then needs read access to the profiles directory. State lives in /var/lib/hermey.
  3. Bridge. Installed into /opt/hermey/venv, run as hermey-bridge.service, bound to 127.0.0.1:8787.
  4. Gateway. Hermes allows one machine-level dashboard per host, so the installer reuses the one already running, reading its port and token from the process environment. Only when there is none does it create hermey-gateway.service.
  5. TLS and reachability. tailscale serve --bg --https=8443 http://127.0.0.1:8787 — a real certificate, tailnet only, no public listener. It then verifies the HTTPS endpoint answers.
  6. The CLI. hermey in /usr/local/bin: status, pair, logs, doctor, update, uninstall.

Never name a unit hermes-gateway.service. That is Hermes' own messaging gateway. The collision is silent until the next restart, when messaging does not come back. Hermey's units are hermey-bridge.service and, only when needed, hermey-gateway.service.

Pairing

hermey pair

It prints a code, a hermes://pair?host=…&code=… link and — when the qrcode package could be installed — a QR. The link carries the address, so it is the one to paste on a Mac that has never paired. The eight digits work on their own only once the app already knows the host.

Codes are single-use and short-lived. Mint one when the phone is in your hand. Pair as many devices as you like; each is individually revocable.

Options

Every flag is also readable as an environment variable, which matters when you pipe the script into a shell.

FlagEnvDefaultMeaning
--port NHERMEY_PORT8787bridge port (loopback)
--https-port NHERMEY_HTTPS_PORT8443tailnet port for tailscale serve
--ref RHERMEY_REFmaingit ref to install; a release tag pins a build
--local DIRHERMEY_LOCAL_SRC—install from a checkout instead of GitHub
--no-serveHERMEY_SERVE=noautodo not touch tailscale serve
--uninstall——remove the units and the serve mapping, keep state
--purge——with --uninstall: also delete state, config and the service user

Paths are overridable too: HERMEY_PREFIX (/opt/hermey), HERMEY_STATE (/var/lib/hermey), HERMEY_CONF (/etc/hermey), HERMEY_BINDIR, HERMEY_USER and HERMEY_UNIT_PREFIX. The last two exist so a second isolated instance can run for testing.

Without Tailscale

The bridge refuses to listen on anything but loopback — that is a design invariant, not a default. If the host has no tailnet, put your own TLS proxy in front of 127.0.0.1:8787 (Caddy with a real certificate is the least work) and pass --no-serve.

sudo bash install.sh --no-serve

A self-signed certificate will not work. The apps follow App Transport Security and refuse it. In this arrangement hermey pair prints the code alone, because there is no address to put in a link — add your public address in the app first, then enter the code.

Uninstall

curl -fsSL https://github.com/macblizzard/hermey/releases/latest/download/install.sh | sudo bash -s -- --uninstall

Stops and removes the units, turns the tailscale serve mapping off, and keeps your state and paired devices. Add --purge to delete /opt/hermey, /var/lib/hermey and /etc/hermey as well.
