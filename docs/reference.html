Reference

The facts a script, an agent or a tired human needs: commands, ports, paths and URLs.

Commands

A Hermey host installs a service, not a CLI of its own — the hermey wrapper belonged to the retired Python bridge. These are the commands a host actually runs; each one is also in Install the host.

CommandWhat it does
…install.sh | sudo shinstall or upgrade hermeyd; the same command both times
sudo setup/install.sh --from-sourcebuild it in a checkout instead of downloading a binary
…install.sh | sudo sh -s -- --uninstallremove the service, binary, config and plugin; state is kept (--purge deletes it)
hermeyd --gateway-checkexits 75 when another gateway owns this HERMES_HOME; it never kills anything
hermeyd --versionthe build installed at /opt/hermey/bin/hermeyd
systemctl status hermeydunit state (macOS: launchctl print system/com.hermeyd)
curl -fsS http://127.0.0.1:8788/v1/healthliveness — the one route that answers without the bearer
tailscale serve --bg http://127.0.0.1:8788publish at serve-root with a real certificate

Ports and units

Host servicehermeyd on 127.0.0.1:8788 (HERMEYD_PORT) — loopback only, by design
Browser channel127.0.0.1:8790 (HERMEYD_BROWSER_PORT) — carries no credential; never published
Bearer/var/lib/hermeyd/local.token (0600, reminted every boot) — what a host-side script sends on 8788
Tailnetserve-root via tailscale serve, real certificate — pairing URLs carry no port
Unitshermeyd.service on Linux; com.hermeyd in launchd on macOS
Nevera unit named hermes-gateway.service — that is Hermes' messaging gateway

Paths

PathWhat
/opt/hermey/bin/hermeydthe service binary
/var/lib/hermeydstate (0700): bridge.db, bridge.salt, local.token, attachments/
/etc/hermey/hermeyd.envconfiguration, 0640, read as an EnvironmentFile
/etc/systemd/system/hermeyd.servicethe unit (macOS: /etc/hermey/com.hermeyd.plist)
<engine>/plugins/hermes-genui/the card plugin, with its desktop/plugin.js bundle
~/Library/Application Support/Hermey/Computer/Workspace/the Mac's shared workspace for computer use

Endpoints

The routes worth knowing by name. The rest are below, generated rather than listed by hand.

URLAnswers
GET /v1/health{"status":"ok","protocol_version":…,"ws":true} on loopback or through the tailnet front door
/v1/pair/startmints a short single-use code; loopback only
/v1/pair/claimthe app presents the code and its public key; a device is registered
/v1/wsthe device websocket (single-use 30 s ticket, then a session)
/v1/local-computers/wsthe Mac's own outbound socket for computer use — the host pings it and drops a silent one
/v1/browser/wsthe sign-in extension's loopback socket; the host sends it a login card's fill, so values never reach the bot

How updates arrive

  • Host: re-run the install command; it is an upgrade and keeps state.
  • macOS: Sparkle reads an appcast and offers the new build in the app.
  • iOS: the sideloading app refreshes from the AltStore source.
