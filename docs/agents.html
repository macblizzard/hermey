For agents

The installation procedure written for an executor rather than a reader: preflight, install, two hard verification gates, then the pairing handoff.

If you are an agent with a root shell on the user's Hermes host, this page is your runbook. The authoritative long form lives in docs/FOR-AGENTS.md; it is also packaged as a skill in setup/SKILL.md.

Who does what

ActorOwns
You (agent)Preflight, install, verification, pairing code, handover of both app links.
The humanThe phone or Mac, and the decision to pair it.
Never youTheir profiles, their bots, their other services, their tailnet configuration.

Runbook

  1. Confirm this is the right host. Hermes must already run here and have profiles the human talks to.
  2. Install. 
    curl -fsSL https://github.com/macblizzard/hermey/releases/latest/download/install.sh | sudo bash
  3. Verify before you say it works. Both gates must pass: 
    hermey doctor
curl -fsS https://<host>.<tailnet>.ts.net:8443/v1/health
    The second answers {"status":"ok", …}. If it does not, do not proceed — go to the failure playbook.
  4. Pair the human's device. Run hermey pair and give them the code or the full link. Do not paste a code into a public channel.
  5. Hand over the apps. The AltStore source for iOS, the downloads page for macOS, and the seven-day re-sign caveat.

Hard rules

  • Never bind the bridge to anything but 127.0.0.1. tailscale serve is the only front door.
  • Never create a unit named hermes-gateway.service. That is Hermes' messaging gateway.
  • Never add App Transport Security exceptions to the apps. The certificate must be real.
  • Never stop or reconfigure an existing tailnet service to free port 8443 — reinstall with --https-port 8444.
  • Do not touch the user's profiles or bots. Hermey reads them; it does not own them.
  • Copy no secrets into chat or logs. Provider keys go in /etc/hermey/providers.env (0600).

Failure playbook

SymptomCauseFix
the bridge did not answer on 127.0.0.1:8787port taken, venv broken, or a crash on starthermey logs 80; sudo ss -ltnp | grep 8787; reinstall with --port 8788
reusing this host's dashboard: pid …a dashboard exists; Hermes allows oneexpected — let it reuse; hermes dashboard --status
doctor health FAIL, audit says upstream_error / connect_failedthe dashboard is not answering, or restarted with a new tokenre-run the installer; it re-reads both
tailscale serve refusednot root, or serve not enabled on the tailnetrun as root; tailscale serve status
HTTPS fails, loopback healthyserve mapping points elsewhere, or wrong DNS nametailscale serve status; --https-port
App connects nowhere, host healthyphone not on the tailnet, or ATS rejecting a self-signed certjoin the tailnet; use the ts.net name
Pairing code rejectedexpired — they are short-livedhermey pair again
iOS app stops launching after ~a weekfree-Apple-ID signature expiredre-sign through AltStore/SideStore

Definition of done

  • hermey doctor — unit active, health ok, HTTPS ok
  • curl against /v1/health answers ok
  • The human has a pairing code or link
  • The human has both app links and knows the iOS re-sign caveat
  • You changed nothing else on the host

Facts you can rely on

Unitshermey-bridge.service always; hermey-gateway.service only if the host had no dashboard
Portsbridge 127.0.0.1:8787 (loopback only), tailnet 8443
Paths/opt/hermey/venv, /var/lib/hermey, /etc/hermey/*.env (0600)
CLIhermey status | pair | logs [n] | doctor | update | uninstall

No tailnet

Install with --no-serve, terminate TLS in front of 127.0.0.1:8787 with a real certificate, and give the apps that URL. Self-signed certificates are refused — do not work around that in the app.
