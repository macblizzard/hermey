Docs / Security

Security and threat model

The tailnet is the wall, the device is the identity, and the client can only answer the questions the agent asks — never give itself permission.

The full document, including the audit and its residual risks, is docs/SECURITY.md. This page is the shape of it.

Trust boundaries

BoundaryCrossing it requiresWhat is on the other side
Public internet → tailnetTailscale identity + ACLnothing: no public ingress exists
Tailnet → bridgeTLS to tailscale serve, then a single-use 30 s ticketpairing, tokens, /v1/ws
Bridge → gatewayloopback plus the gateway token, which is never sent to a devicefull authority over the agent
Gateway → appa server-to-client request (approval, clarify, sudo, secret)a human decision
App → gatewaythe client method allow-listsessions, prompts, discovery

Invariants

  • The bridge listens on loopback only; tailscale serve is the only front door.
  • Tickets are single-use and expire in 30 seconds; a device is identified by its own Ed25519 key.
  • The device never receives the gateway token — it cannot talk to the agent directly.
  • Approvals are the agent's to ask and the human's to answer; a device cannot grant itself authority.
  • Revocation is immediate and per-device.

Deliberately absent

  • No account, no analytics, no crash reporting, no relay of ours in the request path.
  • No public ingress: if the tailnet is up but the device is not on it, nothing is reachable.
  • No per-bot permission system on the Mac. Computer use is one owner-level switch — a small number of trusted bots is the stated model.

Where the apps keep secrets

The phone keeps its device key and refresh token in the Keychain, this-device-only. The Mac build ships unsigned and has no Keychain entitlement, so it keeps the same items in a 0600 file under ~/Library/Application Support/Hermey/, excluded from backups.

Reporting a problem

Open a private advisory at https://github.com/macblizzard/hermey/security/advisories/new rather than a public issue, and do not paste tokens, hostnames or personal data into either.
